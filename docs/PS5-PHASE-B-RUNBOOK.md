# PS5 Phase B: provisioning and runbook

Research checked 21 November 2026 (AEDT, UTC+11). Phase A produced a Prospero ELF and a Linux reference. Phase B requires real PS5 evidence. Its purpose is to run the port against locally supplied data from the owner's disc. [Feasibility plan](PS5-PORT.md) · [PS5 cross-build recipe](../README.md#cross-build-for-ps5)

## 1. Decision tree

| Starting point | Decision |
| --- | --- |
| PS5 with a working local ELF loader and foreground native-title launcher | Keep its existing firmware. Record the full version and qualify both launch contexts in §2 before using it for Phase B. |
| PS5 with an ELF loader only | Use the SDK ELF to qualify the headless context. Full console qualification waits for the unmodified RADV sample to present over HDMI on the same unit. |
| Stock PS5, any firmware | Read the installed version offline. If the owner cannot already demonstrate native homebrew on that unit, Phase B waits for a demonstrated environment. Preserve the installed version if this is a dedicated test candidate. |
| No suitable PS5 on hand | Borrow or buy a unit that can demonstrate both launch contexts offline. Keep working against the Linux null backend while waiting. A working PS4 homebrew setup can support a separate Orbis port experiment. |

Blu-ray Disc Java (BD-J) runs Xlets inside the player’s Java environment. A player-level foothold is evidence about that process. Kernel access is a separate privilege boundary. Even native code executing in a payload process leaves foreground title launch, VideoOut, GPU access and available memory to be measured separately. This runbook starts with an operational ELF loader and omits stock-console exploit chains, firmware targets for those chains and reproduction steps. The public SDK and loader releases are evidence of developer tooling for provisioned consoles. The public RADV template documents foreground rendering on its author’s test unit. [Blu-ray Disc Association BD-J overview](https://us.blu-raydisc.com/wp-content/uploads/sites/2/2019/09/bdj_gem_application_definition-15496.pdf) · [elfldr](https://github.com/ps5-payload-dev/elfldr) · [RADV template hardware results](https://github.com/mihawk-99/PS5_VulkanTemplate#validated-on-hardware)

**Provisioned for Phase B** means the owner can start the known runtime offline after a full shutdown, run an SDK v0.50 ELF with its output reaching the workstation, and run the unchanged RADV foreground sample with HDMI output. On-disk files and launcher icons can survive power-off. Treat the live loader and helper processes as per-boot services and recheck them after each cold boot, even where the owner’s existing setup starts them automatically. The RADV template documents its control helper as once per boot. [SDK v0.50](https://github.com/ps5-payload-dev/sdk/releases/tag/v0.50) · [Websrv documentation](https://github.com/ps5-payload-dev/websrv#quick-start) · [RADV template setup](https://github.com/mihawk-99/PS5_VulkanTemplate)

### Check or acquire a console

1. **Check what is already available.** The read-only ROMs-share audit found a PS5-targeted `ShadowKraken.elf` with Prospero imports, alongside PS4 tools. The inspected firmware-update files belonged to older platforms, the large group of `.sprx` matches came from RPCS3, and the inspected PS5-labelled library folder contained Windows executables. The audit found no installed firmware record or evidence of a successful PS5 launch. Ownership and Phase B readiness remain unconfirmed. [ShadowKraken project identification](https://github.com/MNeroba/ShadowKraken#shadowkraken)
2. **Read the installed version offline.** Disconnect Ethernet and leave known Wi-Fi out of reach or disabled. Boot to the home screen and read **Settings → System → System Software → Console Information**. Record the complete version and the CFI model from the bottom label. A box, date code, seller’s stock photo or listing title cannot establish installed firmware. [Sony firmware menu](https://www.playstation.com/en-au/support/hardware/playstation-system-software-application-version/) · [Sony CFI model location](https://www.playstation.com/en-au/support/hardware/ps5-find-serial-model-numbers/)
3. **Buy on a cold-boot demo.** Ask for an offline cold boot, the version screen, the SDK ELF result and the RADV title on HDMI. Prefer an original disc model, such as CFI-10xxA, 11xxA or 12xxA, if optical media matters. The original Digital Edition cannot use Sony’s clip-on drive. Slim CFI-20xx/21xx and Pro CFI-70xx/71xx can use a detachable drive, which requires an internet connection to pair during setup. If a detachable drive matters, have the seller show it already paired and reading a retail Blu-ray offline on that same unit. An existing digital unit that passes both Phase B tests can use the LAN to stage the owner’s disc dump. [Sony PS5 manuals](https://www.playstation.com/en-au/support/hardware/manuals/) · [Sony drive setup and pairing](https://www.playstation.com/en-au/support/hardware/ps5-disc-drive-set-up/) · [Sony PS5 Pro CFI-71xx manual](https://www.playstation.com/content/dam/global_pdc/en-au/corporate/support/manuals/ps5-docs/7100/CFI-71XX_PS5_Safety_Guide_Web%24en-au.pdf)
4. **Use ordinary used prices as a reference.** Australian refurbished disc listings were about A$800–840 at the time of research. They give a retail comparison and leave the individual unit’s firmware to verify. Prefer a local inspection or a return arrangement with the seller. Skip listings whose only evidence is “homebrew ready”, “never updated”, or a bundled library. [EB Games original disc model](https://www.ebgames.com.au/product/ps5/272442-playstation-5-disc-edition-console-refurbished-by-eb-games-preowned) · [EB Games Slim disc model](https://www.ebgames.com.au/product/ps5/338119-playstation-5-slim-disc-825gb-console-refurbished-by-eb-games-preowned)

**While waiting:** follow the SDK and elfldr release notes for compatibility changes and the RADV project for on-console evidence. elfldr v0.28 and SDK v0.50 both shipped on 20 November AEDT. RADV’s public driver and template document native drawing, VideoOut and test tooling. A release tag or demo on someone else’s hardware cannot qualify the project’s unit. [elfldr v0.28](https://github.com/ps5-payload-dev/elfldr/releases/tag/v0.28) · [SDK v0.50](https://github.com/ps5-payload-dev/sdk/releases/tag/v0.50) · [PS5 RADV driver](https://github.com/mihawk-99/PS5_Vulkan)

**PS4 bridge:** with a working PS4 homebrew environment, start with OpenOrbis `samples/hello_world` and its C++/libc++ build. Then cross-build the portable runtime with the null backend, Vulkan and FFmpeg disabled, retaining the normal Orbis app packaging when moving to hardware. Build for the PS4’s Jaguar baseline. Verify CPUID and OS-enabled vector state before using optimized helper paths. Measure the page size, thread/fibre ABI, 4 GiB + 64 KiB virtual arena and working set. If the runtime needs a scalar or SSE fallback, test it against Linux before lifting the full title. The first milestone is a linked app, a boot log and the synthetic null pixel via an already available launcher. Pad, sound and real rendering need separate Orbis integrations. Choose this bridge if a qualified PS4 is available and the goal is console CPU/ABI experience. Linux remains the direct reference for the portable runtime, and the PS5 qualification still needs Prospero hardware. [OpenOrbis toolchain and samples](https://github.com/OpenOrbis/OpenOrbis-PS4-Toolchain#creating-homebrew-projects) · [OpenOrbis SDL port](https://github.com/OpenOrbis/SDL-PS4) · [Sony PS4 hardware specifications](https://www.playstation.com/en-au/ps4/tech-specs/)

## 2. First night on an already provisioned console

### 1. Pin and qualify the setup

- [ ] Start from a fully powered-off PS5. Connect only to an isolated test LAN with the workstation. Record model, full firmware, date with offset, loader and foreground launcher versions, SDK revision, sample/driver revisions and every deployed binary’s SHA-256. Establish how to exit the test process normally or use the console’s normal shutdown.
- [ ] Have the owner start the verified `elfldr` v0.28 through the console’s existing boot setup, or use it if that setup already starts it. Its raw ELF listener is TCP 9021. On the workstation fetch the pinned Websrv v0.34 asset, compare its GitHub release digest, then send it to the already-running loader. Use the release asset `websrv-ps5.elf` and the command below with OpenBSD netcat. Websrv serves HTTP on TCP 8080. Its PS5 build can register its launcher tile on startup. If another verified Websrv instance is in use, record its version and verify the launch contract before substituting it. [elfldr v0.28](https://github.com/ps5-payload-dev/elfldr/releases/tag/v0.28) · [Websrv v0.34](https://github.com/ps5-payload-dev/websrv/releases/tag/v0.34) · [Websrv startup code](https://github.com/ps5-payload-dev/websrv/blob/v0.34/src/ps5/sys.c#L512-L579)

  ```bash
  # PS5_HOST is the address of the already provisioned console on the test LAN.
  : "${PS5_HOST:?Set PS5_HOST to the test console address}"
  curl -fL -o websrv-ps5.elf \
    https://github.com/ps5-payload-dev/websrv/releases/download/v0.34/websrv-ps5.elf &&
  printf '%s  %s\n' \
    54730c867c6e1148536fdcb370e63a7762d989ea87b62488ad4caff64d43f263 \
    websrv-ps5.elf | sha256sum --check &&
    nc -q 0 "$PS5_HOST" 9021 < websrv-ps5.elf &&
  curl -fsS -o /dev/null "http://${PS5_HOST}:8080/index.html"
  ```

- [ ] On Linux run `readelf -h -l -d` and `sha256sum` on the plain SDK ELF, ABI ELF and port ELF. The Phase A port at `build/ps5-phase-a/PainRecomp.elf` was rechecked at 356,400,776 bytes. It is x86-64 ELF64 PIE with three 16 KiB-aligned load segments, no `PT_INTERP` and ten Prospero imports. Verify the owner’s copy against its recorded build digest. The feasibility staging area still held the C and C++ SDK ELFs under `sample-build/` and the `abi-vm-fiber.elf` probe at review time. If needed, rebuild the C++ `hello_cxx` sample with SDK v0.50. Its expected stdout includes `Hello, libcxx!`. Use the same Websrv command as below with that sample’s staged filename, then test `argv[1]` and environment delivery using the SDK `hello_argv` sample and a tiny environment probe. A transport response alone cannot establish execution. [SDK v0.50 sample sources](https://github.com/ps5-payload-dev/sdk/tree/v0.50/samples) · [Cross-build recipe](../README.md#cross-build-for-ps5)
- [ ] **RADV control.** Recover the exact unchanged feasibility title and its build record if available. The searched artifact locations contained the SDK and ABI ELFs, with no verified RADV sample binary. A documented fallback is the unmodified `Starter` in [PS5_VulkanTemplate at commit 91179df](https://github.com/mihawk-99/PS5_VulkanTemplate/tree/91179df760df1e6c6f2d4d172bc435319d79ff3c). The README’s advertised binary release link returned 404 during review. Build from the pinned source with its documented bootstrap and build tools if recovering the original fails. Record the actual driver and SDK pins. Stage the entire generated title bundle, including `eboot.bin`, `sce_sys`, and sample dependencies, and use the console’s existing native-title launcher. Its textured scene must present and advance on HDMI, then exit cleanly. When using the template’s existing qualification tooling, collect its frame verdict and klog from TCP 3232 if klogsrv is already available. Capture the sample name, driver log and result. Budget a separate first-night task for the RADV build if only source is available. [Template documentation and validation](https://github.com/mihawk-99/PS5_VulkanTemplate#validated-on-hardware) · [RADV display path](https://github.com/mihawk-99/PS5_Vulkan#how-it-works)

### 2. Probe memory before the large payload

- [ ] Run the existing ABI probe in the intended payload context. Confirm `sysconf(_SC_PAGESIZE)`, `mmap`/touch/`mprotect`/`munmap` and the round trip across `getcontext`, `makecontext` and `swapcontext`. The probe exercises a sparse `0x100010000` (4 GiB + 64 KiB) mapping. Phase A’s payload used anonymous private read/write `mmap` without `MAP_NORESERVE`. Test that exact path before trying a different allocator.
- [ ] Extend the probe before counting acceptance runs. Check the toolkit allocator’s 4 GiB alignment wherever `vm_init` is used, 4 KiB guest addressing and host-page-rounded guards. Verify the page beside each guard is accessible. Exercise raw SPU local store at guest offset `0xE0000000 + n * 0x100000` and the problem-state window at `+0x40000` relative to each SPU slot. Touch progressively larger ranges up to the expected working set and log actual process memory, returns, errors and elapsed time. A virtual reservation alone says little about committed pages. Keep the guard fault test in a disposable probe process and stop on exhaustion or inability to recover the expected byte. The Phase A probe is a starting point for these checks. [Memory plan](PS5-PORT.md#sdk--cpu--memory)

### 3. Stage and verify the data

- [ ] Use a dedicated folder such as `/data/homebrew/pain`. Place the host executable at `PainRecomp.elf` and the owner’s disc tree under `disc/PS3_GAME`, including `PARAM.SFO` and the locally prepared guest `USRDIR/EBOOT.elf`. Keep that guest file separate from the host Prospero ELF. The inspected local disc tree was 214 regular files and 1,181,612,118 bytes. Inventory the actual source tree as counts depend on the dump and local preparation. [Runner argument handling](../main.cpp#L424)
- [ ] Seed a **fresh** HDD0 directory with [`extract_cache.py`](../scripts/extract_cache.py). Run it from the repository root with `python3 scripts/extract_cache.py "$DISC_USRDIR/CacheDesc.dat" "$DISC_USRDIR/CacheData.pak" "$SEED_HDD0/game/BCES00548"`. The cache has **8,044 files and 1,061,512,652 payload bytes**, plus the separate five-byte `USRDIR/CacheFlags/CacheDone.flg`. The local cached payload files matched all 8,044 source records by path, size and SHA-256. Six extra files were present in the used tree, so regenerate the seed from the disc archives. For each run create `runs/cold-0N/hdd0`, `hdd1`, and `profile` under the staging folder. Give each HDD0 a copy of the verified seed. This example needs about 4.7 GB before RADV, logs and filesystem overhead. Keep the writable settings file inside that run’s directory.
- [ ] Transfer with the regular [ftpsrv v0.22](https://github.com/ps5-payload-dev/ftpsrv/releases/tag/v0.22) ELF if needed. Send it to the existing loader on TCP 9021 as with Websrv. Use binary-mode FTP on TCP 2121 and copy only into the dedicated folder. Alternatively use an exFAT USB drive for the read-only disc and ELF. Inspect the actual console mount (`/mnt/usbN`), then use its absolute paths. Keep the per-run writable directories on the PS5’s internal storage.
- [ ] Check exact relative names, path case, file counts, sizes and SHA-256 digests for the ELF, disc tree and seeded cache payload files. On Linux, make a sorted size list with `find . -type f -printf '%P\t%s\n' | LC_ALL=C sort`, and a digest list with `find . -type f -print0 | LC_ALL=C sort -z | xargs -0 -r sha256sum` from each source root. Generate equivalent reports on the console, or FTP the staged trees back into a fresh workstation directory and compare both reports with `cmp`. For USB verify the copied media, then confirm the console can read the staged files. Publish the cache completion flag after the payload files match, then read back and verify the flag. Keep manifests and evidence off the public branch. [ftpsrv documentation](https://github.com/ps5-payload-dev/ftpsrv#features)

### 4. Launch and record the three cold runs

Start an evidence directory on the workstation. Run the following once per boot, changing `cold-01` to `cold-02` and `cold-03` for subsequent boots. The path to the native ELF is `path`. Websrv splits `args` and `env` on unescaped spaces, so use console staging paths without spaces. The first argument is `argv[0]`, followed by the guest ELF in `argv[1]`. `daemon=1` selects payload-process launch of the staged ELF via Websrv’s own `elfldr_spawn` path. The version of Websrv matters independently of the TCP 9021 loader version. `pipe=1` returns its diagnostic output. Confirm both stdout and stderr with a known print during qualification. [Websrv v0.34 HTTP handler](https://github.com/ps5-payload-dev/websrv/blob/v0.34/src/websrv.c#L167-L219) · [Websrv v0.34 argument parser and daemon launcher](https://github.com/ps5-payload-dev/websrv/blob/v0.34/src/ps5/sys.c#L95-L154) · [Daemon launch code](https://github.com/ps5-payload-dev/websrv/blob/v0.34/src/ps5/sys.c#L260-L326)

```bash
: "${PS5_HOST:?Set PS5_HOST to the test console address}"
root=/data/homebrew/pain
run_id=cold-01
run_dir="$root/runs/$run_id"
launch_env="PS3_VFS_ROOT=$root/disc PS3_HDD0_ROOT=$run_dir/hdd0"
launch_env="$launch_env PS3_HDD1_ROOT=$run_dir/hdd1 PS3_GAMEDATA_ROOT=$run_dir/profile"
launch_env="$launch_env PAIN_SETTINGS_PATH=$run_dir/settings.ini"
launch_env="$launch_env PAD_AUTOPRESS=1 PS3_STDIO_UNBUFFERED=1 GCM_FLIPCOUNT=1"
launch_env="$launch_env GCM_PUMP_DBG=1 SPURS_PM_CLAIMLOG=1"

curl --fail --show-error --silent --no-buffer --max-time 300 --get \
  --data-urlencode "path=$root/PainRecomp.elf" \
  --data-urlencode "cwd=$run_dir" \
  --data-urlencode "args=PainRecomp.elf $root/disc/PS3_GAME/USRDIR/EBOOT.elf" \
  --data-urlencode "env=$launch_env" \
  --data 'daemon=1' --data 'pipe=1' \
  "http://${PS5_HOST}:8080/hbldr" >"$run_id.log" 2>"$run_id.curl.log"
```

Run directories must exist and be writable before launch. For a bounded trace add `PS3_FTRACE=<start-second>:<duration-seconds>:<absolute-writable-path>` to the launch environment and retrieve the file over the isolated LAN. A curl timeout bounds the connection. Use the established process-stop facility or normal console shutdown to end an active payload. If the stream disconnects, check runtime state before issuing another launch. If the configured loader has no working output pipe, capture a console-local log and verify it can be retrieved before starting the counted runs.

**Three cold runs pass only when all the following hold.** For each attempt power off normally, boot from off, re-establish the known loader services, verify the fresh staged seed and start the same port build and options. Preserve failures. If the build or setup changes, begin a new series. Use five minutes per attempt as an initial diagnostic limit. A timing override or debugger hold belongs in a separate control run.

| Check | Evidence required in each run |
| --- | --- |
| Correct boot and cache | Guest EBOOT and disc roots resolved, correct disc title and cache recognised, and guest progress beyond the install gate. Record the next milestone, including the main-menu milestone when reached. |
| CPU and FIFO | Guest vblank callbacks and flip events recur after the gate. FIFO and completion counters advance across multiple samples, with the expected SPURS workload resolving and actually being claimed or completed. Counters must come from executed work. |
| Memory | Log peak committed/resident memory and at least three samples across 30 seconds of steady post-gate work. Record the budget and tolerance before launch. No allocation failures, stalls or sustained growth at a fixed workload. A sparse debug line may need a sampled counter in the probe to supply this evidence. |
| Null pixel | On that boot, run the synthetic FIFO clear and flip canary using a Prospero build of the toolkit’s `ps3recomp_host` or the equivalent isolated diagnostic. Use `--frames=3` and no draw option for the clear path. The centre pixel from `rsx_null_backend_readback_center()` must report **ARGB `0xFF101830`**. Log expected and observed values via the LAN. The Linux control matched, as did the optional `--draw` triangle at ARGB `0xFFFF0000`. The PS5 canary build and its console result still need evidence. |
| Evidence | Save the runtime and transfer logs, versions, digests, per-run paths, probe samples and stop reason. Compare milestones with the Linux null reference. Preserve separate evidence for the RADV HDMI qualification. |

The Phase A Linux build reached the main-menu callback in 77 seconds under scheduler control, with default scheduling still unverified. If the PS5 stalls around `GameContent` or `SysCacheCreate`, record the event order before changing scheduling, payload or cache. Compare the cold runs against Linux by milestone and counters. Main-menu timing depends on the test setup. PAIN graphics on HDMI belong to Phase C. [Phase B and C gates](PS5-PORT.md#phased-plan-effort-for-one-developer-with-a-qualified-console)

## 3. Firmware and recovery rules

- **Preserve the known firmware.** Keep the dedicated test unit off the public internet and PSN. Disable both **Download Update Files Automatically** and **Install Update Files Automatically**, plus **Stay Connected to the Internet** in rest mode. Decline update prompts from setup, games, discs and USB media. PlayStation’s Safe Mode offers update and destructive reinstall options. Treat an installed update as irreversible for Phase B planning. A factory reset does not roll back the version. [Sony automatic updates](https://www.playstation.com/en-au/support/hardware/automatic-updates-playstation/) · [Sony firmware update paths](https://www.playstation.com/en-au/support/hardware/ps5/system-software/)
- **Verify drive state before purchase or testing.** With a detachable drive, keep the working paired console and drive together. Sony requires internet pairing during setup. Test existing offline reading with a retail disc, and decline any system software prompt. Check original Digital Edition compatibility before buying an accessory drive. [Sony drive setup](https://www.playstation.com/en-au/support/hardware/ps5-disc-drive-set-up/)
- **Limit write scope and protect services.** Use only the dedicated homebrew and run folders. Avoid system partitions, flash, FTP remount commands, update packages and unverified bundled tools. Keep TCP 9021, 8080 and 2121 reachable only by the test workstation on the isolated LAN. Stop the test services or shut down when finished. Keep game-derived binaries, data and private logs out of source control. [Websrv services](https://github.com/ps5-payload-dev/websrv#available-services) · [ftpsrv commands](https://github.com/ps5-payload-dev/ftpsrv#features)
- **Recover in order.** For an app crash, save logs, close the app normally if possible, and restart through the console power menu. Restore the test data from the verified local seed. Use Sony’s storage-repair or restart options for storage/startup symptoms. Back up important data before risky troubleshooting. Reset or reinstall erases local data, and reinstall can change the firmware. Never interrupt storage repair, backup, restore or firmware installation. If the unit cannot boot or storage repair fails, check Sony’s repair options before taking a destructive recovery step. [Sony Safe Mode](https://www.playstation.com/en-au/support/hardware/safe-mode-playstation/) · [Sony backup and restore](https://www.playstation.com/en-au/support/hardware/back-up-ps5-data-USB/) · [Sony reinstall consequences](https://www.playstation.com/en-au/support/hardware/reinstall-playstation-system-software-safe-mode/)
